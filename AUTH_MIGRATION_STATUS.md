## Blockers & Issues

### 1. 🔴 Convex `_generated` Files Don't Exist Yet
The `@convex-dev/better-auth` component needs:
- `convex/_generated/api.js` (for `components.betterAuth`)
- `convex/_generated/dataModel.d.ts` (for `DataModel` type)

These are generated by `npx convex dev`. But `convex dev` fails because the auth code has errors. **Chicken-and-egg problem.**

**Fix:** Need to either:
- a) Start with a minimal working setup, run `convex dev` once to generate files, then build on top
- b) Use the `convex.config.ts` approach where the component handles its own `_generated` files

### 2. 🔴 Schema Generation Failed
`npx auth generate` requires a valid Better Auth config with a database adapter. Without `convex dev` running, we can't create the component client which provides the adapter.

**Fix:** Run `npx convex dev` first (with minimal code that compiles), then generate schema.

### 3. 🟡 `betterAuth()` Bundling Issue
The `convex` plugin from `@convex-dev/better-auth/plugins` failed to bundle in Convex's server-side bundler with "not a function" errors. This may resolve once the correct schema and `_generated` files are in place, since the plugin depends on proper initialization context.

### 4. 🟡 Better Auth Version
Started with `better-auth@1.4.9` which is incompatible with `@convex-dev/better-auth@0.11.2` (requires `>=1.5.0 <1.6.0`). Upgraded to `1.5.5`. The `createAuthClient` API changed between versions — `useSession` is a method on the client instance, not a separate import.

## What Was Learned

1. **`@convex-dev/better-auth` has strict peer deps** — `better-auth` must be `>=1.5.0 <1.6.0`. Always check peer deps before installing.

2. **`better-auth` 1.5.x has a different API than 1.4.x** — `useSession` is a method on the client instance from `createAuthClient` (not a separate import from `better-auth/react`).

3. **Convex component setup requires `_generated` files** — The component client (`createClient`) needs `components.betterAuth` from `_generated/api`, which doesn't exist until `convex dev` runs. This creates a bootstrap problem.

4. **The `convex()` plugin requires `authComponent.adapter(ctx)`** — The database adapter is provided by the component client, not passed separately. The pattern is: `database: authComponent.adapter(ctx)` in `createAuthOptions`.

5. **Schema generation (`npx auth generate`) needs a working config** — It parses the auth config to extract table definitions, so it needs the full plugin chain to resolve.

6. **Don't try to do everything at once** — The migration should be done incrementally: get component registered → generate schema → set up routes → update auth functions → update frontend. Each step should be verified.
